## Shell Lantern module (added 2026-08-03)

User chose Shell Lantern as the 4th module (after Trace Beam / Orbit Seed / Pulse Bloom). First defensive module.

### Mechanics
- `player_.shell` (float) / `player_.maxShell` (cap). Absorbs 1 damage per hit, recharges after delay.
- `DamagePlayer` absorbs shell first (when ≥ 1): shell −= 1, 0.35s i-frames, rechargeTimer reset, flash 0.22s.
- If shell 0, falls through to existing integrity damage path (also resets rechargeTimer).
- Recharge: starts `2.6 − 0.3·level` seconds after last hit, fills at `0.8 + 0.2·level` per second.
- Lv3 evolution: +0.4/s extra regen. Lv5 evolution: maxShell already at 7 (tankier).

### Visuals
- Gold border-only ring (44×44) around player; opacity & alpha tied to `shell/maxShell` ratio; flash boost on hit. Hidden when shell ≤ 0 or module inactive.
- New HUD bar in statusCard (gold gradient, under XP bar) showing "护壳: X/Y". Hidden when module inactive.

### Files changed
- `scripts/main.lua` (705 → 791 lines, still under 1000-line threshold)
- `i18n/zh_CN.json` (added module.shell, module.shell_desc, upgrade.shell, game.shell)
- `i18n/en.json` (same keys)
- `PROJECT_CONTEXT.md` (§3 features, §7 module roster, §11 Goal C checkbox, decision log)

### Pattern for adding a new module
1. Add widget refs (`---@type` annotated, trailing underscore)
2. Update `moduleLevels_` and `activeModules_` to include new id (default 0/false)
3. Add fields to `PlayerState` class + `player_` init values
4. Add i18n keys to inline `TEXT.{zh_CN,en}` and JSON files
5. Extend `ModuleName` + iteration in `ActiveModuleText`
6. Add UI widgets in `BuildGameScreen` + cleanup in `ClearEntities`
7. Reset new fields in `ResetRunState`
8. Update damage routing in `DamagePlayer`
9. Add `Update*` (logic) + `Update*Visual` (rendering) functions
10. Wire calls in `HandleUpdate` (logic before entity updates, visual before HUD)
11. Update `UpdateHUD` for new UI elements
12. Update `ApplyUpgrade` + `PrepareUpgradeChoices` for new id
13. Sync `PROJECT_CONTEXT.md` (§7 module roster, §11 Goal C, decision log)

## Prototype 04 — Defense & Counter (2026-08-03)

User moved on from Shell Lantern to Prototype 04. Chose "Defense & Counter" theme: Anchor Mine + Vector Hook, closing out the §7 six-module roster.

### Anchor Mine mechanics
- Auto-place on cooldown at player's current position. Cooldown: `4.0 − 0.6·level` seconds (3.4s @ Lv1 → 1.0s @ Lv5).
- Each mine is a `mines_` entry with `x`, `y`, `armTimer`, `lifetime`, `detonated`.
- Arm time: 0.3s (0.15s @ Lv3 evolution). Lifetime cap: 6.0s before self-destruct.
- Detonates on enemy proximity (radius `42 + 4·level`); damages all enemies in blast radius (`64 + 8·level`) for 1 + 0.4·level damage. Cooldown resets on detonation.
- Cyan diamond visual with soft glow that brightens at detonation.

### Vector Hook mechanics
- `trail_` array of damage points. Drops new point every `0.10 − 0.02·level` seconds (0.10s @ Lv1 → 0.02s @ Lv5, capped at 0.04s @ Lv3 evolution).
- Only drops when player is actually moving (velocity > threshold) — no static trail.
- Each point lives `0.6 + 0.2·level` seconds, fading via `age / lifetime` curve.
- Damages enemy on contact for 1 (small but frequent). Up to ~40 live points on screen.
- Small magenta dot visual that scales and dims over lifetime.

### Upgrade flow change
- `PrepareUpgradeChoices` switched from "show all available options" to a 3-random Fisher-Yates shuffle of all 8 upgrade ids: `{"trace", "orbit", "pulse", "shell", "mine", "hook", "integrity", "magnet"}`.
- This matches the §11 three-choice spec AND keeps the upgrade screen readable now that the roster is at six.
- `ApplyUpgrade` now handles 6 module ids + 2 global stat ids (integrity, magnet).
